== Lo que debes retener ==
1. DB time = DB CPU + esperas. Si la CPU explica poco del tiempo, la respuesta está en los eventos de espera.
2. «log file sync» se paga en cada COMMIT: se arregla con transacciones del tamaño del negocio, no con discos.
3. Variante de examen: COMMIT WRITE BATCH NOWAIT también lo reduce, pero renuncia a la durabilidad inmediata.
Un DBA no la propone sin que el negocio acepte perder las últimas confirmaciones si cae la instancia.
4. Dentro de un bucle PL/SQL Oracle no espera en cada COMMIT (optimización de PL/SQL): mide siempre como
trabaja la aplicación real (aquí, COMMIT WRITE WAIT), o el laboratorio te dará una cifra que producción no verá.
